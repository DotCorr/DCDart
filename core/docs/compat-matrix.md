# Compatibility matrix

Every Dart package/library touched, its compat tier, what broke, what was done. Populated from M5
onward (corpus sweep); kept here from the start so the format is settled before volume hits.

Tiers: T0 (byte-identical behavior) … T5 (does not work, documented why).

| Package/library | Tier | What diverged | Notes |
|---|---|---|---|
| `dart:core` / `dart:isolate` — shared-memory concurrency | n/a | **No upstream counterpart exists to diverge from.** Dart's concurrency model is isolates with no shared mutable memory, so upstream Dart has no atomics API at any layer — not in `dart:core`, not in `dart:isolate`, and `dart:ffi` never added one. | ADR-0055 (`Atomic.*`) and ADR-0056 (`fence(Ordering.…)`) are therefore pure DCDart extensions in `dc:core.bare`, not reimplementations. No upstream Dart program can call them and none can break on them. Recorded because the natural assumption — "surely `dart:ffi` has atomics" — is wrong, and a porting agent that assumes otherwise will look for a mapping that does not exist. |
| `dart:core` — `String.length` | **T3** | **`"héllo".length` is 6 in DCDart and 5 in upstream Dart.** Dart counts UTF-16 code units; DCDart's `Str.length` counts UTF-8 bytes. | ADR-0053. This is the largest deliberate semantic divergence in the language so far, and the most dangerous shape a divergence can take: **silently correct for pure ASCII, silently wrong at the first non-ASCII byte.** It will pass hand-written tests and fail in the field. `Str` is a distinct type (`extension type const Str(String)`) rather than an alias specifically so that `dart:core`'s `String.length` cannot be reached by accident — an earlier attempt exposed `.length` on plain `String` and the frontend resolved it to the upstream getter, returning code units, with no error anywhere. Asserted twice in `tests/conformance/str/`: at runtime, and on the emitted IR (a `[5 x i8]` global would mean the literal was *measured* in code units, not merely reported as such). |
| `dart:core` — function expressions and local functions (closures) | **T4** | **A closure that captures anything is a compile ERROR, not slower code.** Upstream Dart closures capture their enclosing scope; DCDart lowers only the subset that captures nothing. `() => x + 1` inside a function taking `x` does not compile. Nor does passing, returning or storing a function value at all — `List.map`, callbacks and any higher-order API are unreachable. | ADR-0057, and read it with `docs/escalations/0008` open. **Do not read this row as "closures work".** What works is a local function called by name: it hoists to an ordinary static symbol and is called directly, with zero allocation and zero ARC difference from writing it at top level (`tests/conformance/closure/` asserts the ARC counts are identical, not merely the values). The two missing halves are missing for *different* reasons and neither is a lowering: capture needs an environment, hence a heap, hence escalation 0002 (open); a function VALUE needs a DC-IR indirect call that does not exist (GAP-0052). The second one also removes the fact elision depends on, so the honest expectation is that closures-as-values arrive slower than this row's subset, not equal to it — escalation 0008 §3. |
| `dart:core` — generic CLASSES (`class Box<T>`) | **T2** | **Instantiation is a compile-time act with a symbol, not a runtime one.** Upstream Dart generic classes are reified: `Box<int>` and `Box<String>` share one class, one set of method bodies, and carry their type arguments at runtime, where `is`/`as` and `runtimeType` can see them. DCDart monomorphizes: `Box<u64>` and `Box<Node>` are separate emitted layouts, separate method bodies (`Box$u64_unwrap`, `Box$Node_unwrap`) and separate destructors, with no type argument surviving to runtime. | ADR-0054. Source-compatible for the code M3 needs — writing and using a generic container reads identically — so the divergence is in what a program can OBSERVE, not in what it can say. The three things that break are `runtimeType`, a type test against a type argument (`x is Box<T>`), and reflection over one; the first two do not exist in DCDart's subset and the third is escalation 0004. **Unbounded instantiation is a compile ERROR, not an infinite compile**: `f<T>` calling `f<Box<T>>` is legal upstream and rejected here, with the depth named. Also unlike upstream: generic METHODS on classes are not implemented at all (GAP-0055). |
